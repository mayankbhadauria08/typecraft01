DATA, DATABASE AND APIS (build this fully)
------------------------------------------
Goal: nothing a learner does is ever lost, and no number is ever different in
two places. Example: someone stops in the middle of lesson 3. On any device,
after signing in, Continue opens lesson 3 at the same step, and that lesson's
scorecard shows the same stars, best speed, accuracy and attempts.

Start by reading the server code that is already there (the Worker, its routes
and its database tables) and tell me what it stores today. Then extend it. If
the server code is not in the folder, ask me for it. If I say there is none,
build the whole server new on Cloudflare Workers with a D1 database, including
sign-up and sign-in, and tell me that existing accounts will have to be moved.

One rule decides every number: for a signed-in learner the database is the
truth. The browser keeps a copy for speed and for working offline. Totals
(stars, best speed, XP, rank, streak, badges) are worked out on the server from
the saved events, never taken from the browser's own totals.

What goes in the database, every row tied to the user:
 1. Runs. Every finished step, lesson, test, boss fight and game run: an event
    id made in the browser, the lesson or game id, the step, speed, accuracy,
    errors, seconds, stars, crown, XP given, device time, server time.
 2. Lesson progress. Per lesson: status (not started, in progress, completed),
    current step, stars, crown, best speed, best accuracy, attempts, last
    played.
 3. Position. The lesson and step the learner is on right now, saved when a
    lesson is opened and after every step.
 4. Typing statistics. Hits and misses per key, timing per key pair, and
    mistake types (today's KeyStats, BigramLatency and ErrorClasses), sent in
    small batches.
 5. Daily totals. Per day: minutes practised, runs, best speed, average
    accuracy, XP, quests done. This feeds the calendar, the charts and the
    streak.
 6. The XP ledger and rank, the streak with freezes used, daily quests and
    their state.
 7. Badges earned with their dates, certificates issued, the placement result.
 8. Workshop: what is unlocked and what is in use (keycaps, ink, paper, sound),
    and settings (theme, effects, sound level, daily goal, finger guide).
 9. Game bests per game, ghost replays (best-run timings, capped in size),
    Daily Challenge results.
10. Feedback entries (today they stay in the browser; send them to the server
    too).

APIs. All under /api, for the signed-in user only, JSON, using today's sign-in
session:
- GET  /api/user/state         Everything the app needs at start in one call:
                               progress for every lesson, position, totals, XP
                               and rank, streak, quests, badges, unlocks,
                               settings, game bests.
- POST /api/user/events        A batch of events (run finished, step finished,
                               quest progress). Each has a unique id. The
                               server ignores an id it has already saved and
                               answers with the fresh totals.
- PUT  /api/user/position      The lesson and step just opened or finished.
- POST /api/user/stats         A batch of typing statistics.
- PUT  /api/user/settings      Settings and what is in use from the Workshop.
- GET  /api/user/lessons/:id   That lesson's scorecard: best, last, attempts,
                               stars, crown, and every run with its date, speed
                               and accuracy.
- GET  /api/user/history       Daily totals for the calendar and charts.
- POST /api/user/import        Adds a guest's browser progress to the account
                               (today's "Add your earlier progress?" step),
                               keeping the better result for each lesson and
                               never counting a run twice.
- GET  /api/user/export        The learner's whole data as a file.
- Deleting the account removes every row listed above.
Keep today's routes working until the new ones have fully replaced them.

Rules that prevent a mismatch:
- Every write is an event with an id made in the browser. Sending it twice
  changes nothing.
- Counters are updated in one database statement, never read first and written
  back afterwards.
- The server checks every number (speed 0 to 400, accuracy 0 to 100, sensible
  seconds, a lesson id that exists) and refuses anything else.
- Offline: events wait in the browser's queue (today's sync queue) and are sent
  in order when the connection returns. Until then the screen says "Saved on
  this device, will sync".
- After every sync the browser replaces its totals with the server's answer.
- Two devices at once: events from both are kept, the best result per lesson
  wins, and the position is the most recent one by server time.
- A guest's data stays in the browser in the same shape, so signing up loses
  nothing.

Pipelines:
- On every event batch: save the events, then update lesson progress, daily
  totals, XP, streak, quests and badges together, so they can never disagree.
- A nightly job (a Cron Trigger) rebuilds every total from the saved events and
  compares it with the stored total. It corrects any difference and records it.
- An owner-only page with the health numbers: learners, active today, runs
  today, events waiting or failed, and differences found by the nightly job.
  That last number should be zero.

Scorecard: every lesson card, the lesson screen and the Results screen show the
same scorecard from the server: stars, crown, best speed, best accuracy,
attempts, last played and the run history. The Continue button reads the saved
position.

Safety: change the database only through numbered migration files. Run them on
a local or test database. Do not run a migration on the live database and do not
deploy: give me the commands and I run them after I approve. Never print
passwords, tokens or other secrets.

INSIDE EVERY LESSON: FIVE STEPS
-------------------------------
1. Watch (new). About five seconds, not scored, with a Skip button. The 3D
   keyboard shows the lesson's new keys, the finger that presses each and its
   reach line. For a lesson with no new keys it shows what the lesson is about.
2. Keys. Today's "character" step.
3. Words. Today's "word" step.
4. Sentences. Today's "paragraph" step.
5. Challenge (new). Thirty seconds on this lesson's own words against the
   level's speed target.

- The three early lessons that have no real words keep today's behaviour: Keys
  is followed by today's "mixed" step instead of Words and Sentences.
- Timed lessons and tests keep a single timed step. Review lessons, bosses and
  Pro lessons may use fewer steps.
- Today the timed text is taken from Mastery paragraphs. Timed and Challenge
  steps in earlier levels must take text from that lesson's allowed words.
- Stars are worked out as today. Crown: finish Challenge at or above the level
  target with 95% accuracy or better. Targets in words per minute: Beginner 12,
  Intermediate 18, Advanced 24, Mastery 35, Pro 30.

Placement test: a first-time visitor is offered a 2-minute test, which can be
skipped. Below 15 words per minute or below 85% accuracy suggests Level 1; 15 to
25 suggests Level 2; 25 to 35 suggests Level 3; above 35 at 92% or better
suggests Level 4. It is only a suggestion.

BOSS BATTLES
------------
A boss ends each unit and uses only that unit's keys. The boss has a health bar.
Each correct word hits it, by the word's length. Each mistake heals it a little
and shakes the screen. A timer bar is the boss's attack: when it empties the
learner loses one of three hearts. Words get harder in three phases. The boss is
beaten when its health reaches zero with 90% accuracy or better; below 90% it
escapes and the learner can retry. Rewards: XP and badge progress.

THE ARCADE: EIGHT GAMES
-----------------------
Every game uses only keys the learner has learned (the allowed set of the
furthest lesson they have completed; with no progress, the home row). Every game
ends with a score, the learner's best, XP earned, Play again and Back.

1. Word Storm. Rebuild today's falling-words game and give it this name (today
   it is labelled Space Invaders). Words fall; typing one destroys it; long
   words are bosses that take several hits; three lives. Add waves that speed
   up every ten words, gold power-up words ("freeze" slows everything for five
   seconds, "clear" empties the screen), a combo multiplier for words cleared
   without a wrong key, a starfield with depth, and particle bursts.
2. Beat Keys. Rebuild today's Metronome as a lane drawn in perspective. Letters
   ride toward a hit line on the beat. Within 60 ms of the beat is Perfect,
   within 160 ms is Good, otherwise Miss. Speeds 60, 80, 100, 120 and 140 beats
   a minute. Combo and on-beat percentage as today.
3. Tug-of-War. Rebuild today's game as best of three rounds with an animated
   rope and flag. Three kinds of bot: Steady, Sprinter (fast start, then
   fades), Late Surger (slow start, fast finish). Speeds 30, 45, 60 and 80
   words per minute as today.
4. Ghost Race (new). Save the key timings of the learner's best run for each
   passage length. Race that replay and three bots on a track drawn in
   perspective. With no saved run yet, race the bots and record one.
5. Key Pop (new). Balloons carry single letters upward. Pressing the letter
   pops it. Five escaped balloons end the game. Speed rises slowly. Built for
   beginners.
6. Word Tower (new). Sixty seconds. Each correct word adds a block to a 3D
   tower. A mistake makes the tower wobble and removes the top block. Height is
   the score.
7. Safe Cracker (new). Codes made of digits and symbols the learner knows. Each
   correct code turns the dial; three codes open a safe; the time per safe
   shrinks. If the learner has not reached the number row, offer a letters-only
   easy mode.
8. Boss Battles. The course bosses, replayable here once met.

Daily Challenge: one passage a day, chosen from the date so it needs no server.
The first finished run of the day counts and is compared with the learner's own
earlier days.
